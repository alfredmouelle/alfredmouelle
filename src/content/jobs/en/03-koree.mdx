# QA testing and mobile development for Koree

## Context

Koree is a fintech application in Francophone Africa designed to eliminate merchant coin shortages by digitizing change into wallet balances and loyalty cashback. The ecosystem spans a consumer mobile application, a merchant app (Koree Pro), and a central Laravel backend. Because transactions directly affect customer wallets, automated tests were essential to avoid payment regressions on every release.

## My role

Working as a freelance QA tester and developer, I set up automated end-to-end browser tests, wrote backend test suites with PestPHP and Postman, and fixed bugs directly across the Flutter app and Laravel API.

## What I built

- **E2E test suites with Cypress**: automated browser tests covering critical flows in Koree and Koree Pro (onboarding, cashback calculation, and cashier transactions).
- **Backend testing with PestPHP**: unit and integration tests covering wallet balance calculations, transaction logic, and request validation rules in the Laravel API.
- **API validation with Postman**: automated collections to verify JSON payloads, HTTP status codes, and auth token refresh flows.
- **Flutter mobile bug fixes**: patched layout glitches, state synchronization issues, and offline edge cases.
- **Laravel backend fixes**: resolved validation gaps and SQL bottlenecks flagged by the test suites.

## Key takeaways

On a micro-transaction app, a wallet balance discrepancy instantly ruins trust for both the cashier and the customer. Covering calculation logic with PestPHP and cashier flows with Cypress prevented silly regressions from reaching production.
